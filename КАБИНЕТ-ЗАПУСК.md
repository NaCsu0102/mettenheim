# Как запустить личный кабинет «Хроник Меттенхейма»

Кабинет — это вход через Discord, свои персонажи, отправка квент на проверку и кабинет мастера.
Данные хранятся в Supabase (бесплатный тариф), сайт лежит на любом статическом хостинге.
На всё уходит 20–30 минут. Программировать ничего не нужно — только скопировать пару значений.

Что лежит в архиве:
- `index.html` и остальные файлы — сам сайт;
- `config.js` — сюда вписываются адрес и ключ Supabase;
- `supabase/schema.sql` — таблицы и права доступа, выполняется один раз;
- этот файл.

---

## 1. Выложить сайт (чтобы появился адрес)

Адрес сайта нужен для настройки входа, поэтому начинаем с него.

**Самый простой способ — Netlify Drop**
1. Зайди на https://app.netlify.com/drop и зарегистрируйся (можно через GitHub или почту).
2. Распакуй архив и перетащи **всю папку** с сайтом в окно браузера.
3. Через минуту появится адрес вида `https://имя-сайта.netlify.app`. В настройках (Site configuration → Change site name) его можно переименовать, например в `mettenheim.netlify.app`.

**Или GitHub Pages**
1. Создай публичный репозиторий на GitHub.
2. Залей туда файлы сайта через GitHub Desktop (через веб-окно можно грузить только по 100 файлов за раз, а их больше 400).
3. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
4. Адрес будет `https://твой-ник.github.io/имя-репозитория/`.

Запиши адрес сайта — дальше он называется **АДРЕС_САЙТА**.

## 2. Создать проект Supabase

1. Зайди на https://supabase.com → Start your project → войди через GitHub.
2. New project: имя `mettenheim`, придумай пароль базы (сохрани его), регион — **Central EU (Frankfurt)**.
3. Подожди пару минут, пока проект создаётся.

## 3. Создать таблицы

1. В левом меню Supabase открой **SQL Editor** → New query.
2. Открой файл `supabase/schema.sql` любым блокнотом, скопируй всё и вставь в окно.
3. Нажми **Run**. Должно появиться `Success. No rows returned`.

Файл можно запускать повторно — он ничего не ломает и не стирает данные. Если ты уже запускал старую версию, просто запусти новую поверх.

## 4. Включить вход через Discord

**В Discord:**
1. Открой https://discord.com/developers/applications → **New Application**, назови «Хроники Меттенхейма».
2. Слева **OAuth2**. Скопируй **Client ID**, нажми **Reset Secret** и скопируй **Client Secret**.
3. В блоке **Redirects** нажми Add Redirect и вставь:
   `https://АДРЕС_ПРОЕКТА.supabase.co/auth/v1/callback`
   (точный адрес Supabase показывает на следующем шаге, в поле Callback URL — можно взять оттуда). Сохрани.

**В Supabase:**
1. **Authentication → Sign In / Providers → Discord** → включи.
2. Вставь Client ID и Client Secret из Discord → Save.

## 5. Сказать Supabase, где живёт сайт

**Authentication → URL Configuration:**
- **Site URL** — АДРЕС_САЙТА, например `https://mettenheim.netlify.app`
- **Redirect URLs** → Add URL — тот же адрес. Для GitHub Pages — вместе с именем репозитория и слешем в конце.

Без этого шага после входа через Discord игрока вернёт на чужую страницу.

## 6. Вписать ключи в config.js

1. В Supabase: **Project Settings → Data API** (или **API**) — скопируй **Project URL**.
2. **Project Settings → API Keys** — скопируй ключ **anon public** (или **publishable**).
3. Открой `config.js` и впиши:
   ```js
   window.MH_SUPABASE = {
     url: 'https://abcdxyz.supabase.co',
     anonKey: 'eyJhbGciOi...',
     discord: true,
     email: true
   };
   ```
4. Залей сайт заново (в Netlify: Deploys → перетащи папку ещё раз; в GitHub — закоммить файл).

Этот ключ публичный по задумке: его видно любому, кто откроет сайт. Данные защищают правила доступа из `schema.sql` — игрок видит и правит только своё, проверять может только мастер.
**Никогда не вставляй ключ `service_role` / `secret`** — он открывает всю базу.

## 7. Назначить себя администратором

1. Открой сайт → **Кабинет** → **Войти через Discord**. Так создастся твой профиль.
2. В Supabase → SQL Editor выполни (подставь почту, привязанную к твоему Discord):
   ```sql
   update public.profiles set role = 'admin'
   where id = (select id from auth.users where email = 'твоя@почта');
   ```
3. Обнови страницу сайта — в кабинете появится переключатель **Кабинет мастера**.

Остальных мастеров назначай прямо на сайте: Кабинет мастера → вкладка **Игроки и роли** → роль «Мастер». Игрок сначала должен один раз войти на сайт.

## Как это работает

**Игрок**
- Входит через Discord (или по ссылке на почту) — профиль создаётся сам.
- Создаёт персонажей. Кнопка «Взять из анкеты» переносит анкету с главной страницы, «Прикрепить сборку» — его древо талантов.
- Пишет квенту частями, сохраняет черновик. Для отправки нужны имя, народ, класс и квента от 1500 знаков.
- Пока квента на проверке, править её нельзя — можно отозвать в черновик.
- Ответ мастера и переписка — в карточке персонажа.

**Мастер**
- Видит очередь «На проверке» в порядке отправки, ищет по имени, игроку и народу.
- Читает анкету, портрет, сборку древа и квенту на одном экране.
- Принимает, возвращает на доработку или отклоняет. Для доработки и отказа комментарий обязателен.
- Вся история решений сохраняется.

**Ограниченные места.** Инферналов и проклятых на сервере может быть по 7 одновременно. Место занимает принятая квента. Когда все 7 заняты, новую заявку нельзя отправить, а мастер не сможет принять лишнюю. Счётчик «свободно N из 7» виден на страницах народа, проклятых, в анкете и в кабинете, даже без входа. Чтобы освободить место, мастер переводит персонажа в архив (Table Editor → characters → status = archived) или отклоняет. Лимит меняется в `supabase/schema.sql`, функция `slot_limit`.

**Статусы:** Черновик → На проверке → На доработке / Принята / Отклонена.
Принятую или отклонённую квенту игрок править не может — только мастер.

## Если что-то не так

- **«Кабинет ещё не подключён»** — `config.js` пустой или сайт не перезалит после правки.
- **После Discord попадаю на localhost или другой сайт** — проверь шаг 5: Site URL и Redirect URLs.
- **Discord пишет «Invalid OAuth2 redirect_uri»** — в Discord Redirects должен быть адрес `…supabase.co/auth/v1/callback`, а не адрес сайта.
- **Письмо для входа не приходит** — встроенная почта Supabase шлёт всего несколько писем в час и годится для проверки. Для живого сервера подключи свою почту (Authentication → Emails → SMTP Settings) или оставь только Discord: `email: false` в `config.js`.
- **Проект «уснул»** — бесплатный проект Supabase ставится на паузу после недели без единого запроса. Достаточно нажать Restore в панели. Пока сайтом пользуются, пауз не будет.

Квенты можно выгрузить в любой момент: Supabase → Table Editor → `characters` → Export → CSV.
